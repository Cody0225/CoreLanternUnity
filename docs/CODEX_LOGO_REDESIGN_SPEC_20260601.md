## 背景: 現行ロゴの何がダメか (作り直しの理由)

現行 `GameLogo.png` / `GameLogo_TitleCompact.png` は以下の理由でアマチュアに見える。
作り直しでは**これらを必ず避ける**こと。

| 現行の問題 | 対策原則 (Web リサーチ準拠) |
|---|---|
| `EGGCORE`(青グラデ立体) と `PROTOCOL`(細い金) で**書体が完全に別物** | 単一の統一書体方向にする。2語が同じデザイン言語に属すること |
| `O` の中に**電球のようなマーク**が入って浮いている | シンボルは文字と意味的に統合されてこそ。中途半端な装飾アイコンは禁止 |
| 下に**安っぽい金の下線** | 雑な装飾線はアマチュア印。装飾は最小限・意味のあるものだけ |
| 全体に**フリー素材感** | メタリック質感 / 繊細なグラデ / neon glow で「深み」を出す |

参考にした原則:
- sci-fi の geometric sans serif は定番だが「ひとひねり」で差別化
- 複数フォント混在を避け、ロゴ全体を1つのデザイン言語で統一
- 小サイズに縮小しても可読性が保たれる (Steam header 460x215 でも読める)
- グロウ/メタリック等のテクスチャで flat から脱却

## デザイン仕様 (クール・サイバー統一系)

### コンセプト
「夜のデータ防衛任務」。冷たく洗練された近未来。Hades / Hyper Light Drifter / Returnal の
タイトルロゴのような、**静かで高級感のあるサイバー感**。けばけばしくしない。

### タイポグラフィ
- **書体**: geometric sans-serif 1種で `EGGCORE PROTOCOL` 全体を統一
  - 推奨イメージ: Eurostile / Orbitron / Rajdhani 系の「角に少し丸みのある幾何学サンセリフ」
  - ただし定番すぎないよう、**字幅をやや広め (tracking +)** にして呼吸感を出す
- **2語の関係**:
  - `EGGCORE` = 主役。大きく、太め (Bold)
  - `PROTOCOL` = 従属。`EGGCORE` の下に、**同じ書体のまま**小さく・字間を広げて配置
  - 例:
    ```
        E G G C O R E
        P R O T O C O L   ← 同書体・小さめ・字間広め
    ```
- **禁止**: 2語で別フォントを使うこと。立体押し出し(extrude)の多用。袋文字の重ねすぎ

### カラー (ブランド準拠)
- 主体: 青白 `#8BC8FF` (core 光)
- 輪郭/アクセント: 燻った赤 `#C84A1F` は**ごく控えめ**に (例: 細いエッジライン1pxだけ、または完全に省略可)
- 背景透過 (四隅 alpha=0)
- **グラデは縦方向に繊細に** (上=明るい青白 → 下=やや沈んだ青)。けばけばしい虹色グラデ禁止
- neon glow は**ぼんやり弱め**に1層だけ。光らせすぎない

### シンボル (任意・入れるなら意味的に)
- 電球マークは**廃止**
- もし入れるなら: `C` または `O` の字形に、**データエッグ(Lantern)を連想させる細い同心リングの輪郭**を
  さりげなく溶け込ませる程度。文字の可読性を損なわないこと
- 無理に入れず、**文字だけで完成させる方が安全**。シンボルは「あれば良い」程度

### 装飾
- 安い下線は**廃止**
- 入れるなら: 文字の左右に伸びる**極細(1-2px)のテックライン**を片側だけ、左右非対称に。
  ただし `Title_LogoUnderline_v2` のような主張する横線は不要

## 出力ファイル

| ファイル | サイズ | 用途 |
|---|---:|---|
| `GameLogo.png` | 1024x512 | 汎用/ストア用 (上書き) |
| `GameLogo_TitleCompact.png` | 1024x320 | タイトル画面用・上下余白詰め (上書き) |
| `GameLogo_Mono.png` | 1024x512 | モノクロ版 (上書き) |

- 全て透過 PNG、四隅 alpha=0
- `_TitleCompact` はタイトル画面で `(620x194)` 枠に preserveAspect 表示される。
  この枠でロゴ本体が小さくなりすぎないよう、上下の余白を詰めて文字を大きく
- 縮小耐性: 460x215 相当に縮めても `EGGCORE` が読めること

## 🔴 meta 生成の必須ルール (今回の不具合の再発防止)

2026-06-01、Codex が生成した V2 素材の `.meta` が**末尾改行欠落 + 改行コード不正**で
Unity が「could not be parsed / valid GUID なし」として PNG ごと無視する不具合が発生した
(77枚)。**今回のロゴ素材で同じ事故を起こさないこと。**

`.meta` を書き出す場合は必ず:
- **UTF-8 (BOMなし)**
- **改行コード CRLF** (または既存 Lantern.png.meta と byte 整合する形式)
- **ファイル末尾に改行を必ず1つ付ける** (末尾が `assetBundleVariant:` で改行なし終端は NG)
- 既存の正常 meta (`Assets/Resources/Skins/Lantern.png.meta`) をテンプレに、GUID 行だけ
  ユニークな32桁hexに差し替える方式が安全
- **生成後、自分で末尾バイトが 0x0a であることを検証してから完了報告する**

PowerShell で書くなら:
```powershell
# 末尾改行 + CRLF + BOMなし の例
$text = ($lines -join "`r`n") + "`r`n"
[System.IO.File]::WriteAllText($path, $text, [System.Text.UTF8Encoding]::new($false))
# 検証
$b = [System.IO.File]::ReadAllBytes($path)
if ($b[-1] -ne 0x0a) { throw "meta 末尾改行なし: $path" }
```

理想は **PNG だけ置いて .meta は Unity に自動生成させる** こと
(Unity Editor を開けば正しい .meta が自動で作られる)。手書き meta は事故の元。
