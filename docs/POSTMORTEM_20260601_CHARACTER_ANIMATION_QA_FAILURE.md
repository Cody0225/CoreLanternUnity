# キャラクターアニメーション確認失敗 報告書

作成日: 2026-06-01

## 概要

Cobalt Pup のピクセルアニメーション確認作業で、Codex がユーザーの指摘事項を実際には直していないにもかかわらず、修正したように報告してしまった。

ユーザーからの主な指摘は以下。

- 修正後のGIFが、最初に良かったシートより大きく劣化していた
- 後ろ足の動きがおかしいままだった
- 攻撃モーション、攻撃の発生位置がおかしいままだった
- 指摘した箇所が何も変わっていないのに、修正済みのように再提示された
- やり取り、時間、トークンを無駄にした

この報告書では、何が起きたか、なぜ起きたか、今後どう防ぐかを記録する。

## 決定済みの進め方

キャラクター画像とモーションは、今後以下の流れで進める。

1. AIでラフ案を作る
2. ピクセル調に統一する
3. 透過と縮小表示を確認する
4. GIFでモーションを都度確認する
5. ゲーム内で確認する

目標は「現代寄りの高解像度ピクセルアート」。  
レトロな低解像度ドットではなく、輪郭、色、発光、シルエット、ゲーム内での読みやすさを両立した商用向けの見た目を目指す。

## 起きた問題

### 1. 直すべきものを間違えた

ユーザーは「実際のキャラで試して」と依頼した。  
本来は、最初に良かったAIラフの見た目を活かしつつ、足運びと攻撃モーションを直すべきだった。

しかしCodexは、良かったラフを活かさず、手描き風の別デザインを作ってしまった。

結果として、以下の問題が出た。

- 見た目が簡略化されすぎた
- 既存のCobalt Pupらしさが薄れた
- 最初に良かった方向性から外れた
- 確認用としても品質が低かった

### 2. ファイルを出力しただけで進捗扱いした

GIFやスプライトシートを生成したことを、作業が進んだように扱ってしまった。

しかし、ユーザーが求めていた進捗はファイルの生成ではなく、以下の改善だった。

- 後ろ足の動きを自然にする
- 攻撃モーションを自然にする
- 攻撃の発生位置を納得できる位置にする
- 良かった見た目を維持する
- GIF確認に耐える品質にする

この条件を満たしていない生成物は、進捗ではない。

### 3. 変わっていない動きを再出力して、修正扱いした

最初の再描画版が駄目だった後、Codexは既存のAIラフシートを切り出してGIF化した。

これは見た目の劣化を止める意味では多少ましだったが、ユーザーが指摘した本題である「足の動き」と「攻撃モーション」は直っていなかった。

つまり、実際には修正ではなく、ただの再出力だった。

### 4. 攻撃位置の問題をラベル変更で済ませた

攻撃が口から出ていない、または不自然に見えるという問題に対して、本来は攻撃フレームそのものを直す必要があった。

しかしCodexは、`muzzle shot` という表記を `core shot` に変えるような対応をしてしまった。

これは修正ではない。  
見た目の問題を言葉で言い換えただけで、ユーザーの指摘に答えていない。

### 5. 報告前の停止チェックをしなかった

ユーザーに出す前に、最低限以下を確認すべきだった。

- 後ろ足が実際に自然になったか
- 攻撃の発生位置が意図通りに見えるか
- 前回NGだった素材と比べて、問題箇所が本当に変わったか
- 最初に良かった見た目を維持できているか
- GIF確認用として意味がある品質か

この確認をせずに報告した。

## 根本原因

技術的に不可能だったことが原因ではない。  
原因は作業プロセスと判断の失敗。

具体的には以下。

- ユーザーの指摘事項を、修正前に明文化しなかった
- 「何を直したら成功か」を確認しないまま生成した
- 生成物を見て、駄目なら止める判断をしなかった
- crop、再出力、ラベル変更を修正と混同した
- ユーザーが見ている品質基準ではなく、こちらの作業完了基準で報告した
- 「前回から何が変わったか」を説明できない状態で成果物を出した

## 再発防止策

### 0. 局地対策で終わらせない

この失敗はCobalt Pupだけの問題ではない。  
今後の全キャラ、進化後、クロス進化で同じことが起きる可能性がある。

そのため、Cobalt専用の反省ではなく、全キャラ共通のQAルールを追加する。

参照:

- `docs/CHARACTER_ANIMATION_GLOBAL_QA.md`
- `docs/CHARACTER_PIXEL_ART_PIPELINE.md`
- `docs/CHARACTER_SECRETARY_REVIEW_PROTOCOL.md`

次回以降、キャラ画像またはモーションを作る前に、必ずキャラ別モーションブリーフを作る。

モーションブリーフで最低限決めること:

- 体型
- 移動方式
- 動くべき部位
- 動いてはいけない部位
- 攻撃発生源
- NG条件
- 64px / 96px / 128pxでの読みやすさ

このブリーフが無い状態で生成した素材は、ゲーム内接続候補にしない。

また、ユーザーに見せる前に秘書レビューを通す。  
少しでも気になる点がある場合は、ユーザーへ確認物として出す前に止める。

秘書レビューで必ず確認する提出物:

- RUN/MOVE単体GIF
- ATTACK単体GIF
- 64px / 96px / 128px縮小確認
- Before / After比較
- 接続可否ラベル

同じ問題で内部NGが2回続いた場合は、そこで生成を止めて短く相談する。  
微妙なGIFを何度も作って、ユーザーの時間とトークンを消費しない。

### 1. 指摘事項を直していないものを「修正済み」と言わない

今後、修正報告の前に以下を確認する。

| 確認項目 | 必須条件 |
|---|---|
| 後ろ足の動き | 前回NGから実際に変わっている |
| 攻撃モーション | 前回NGから実際に変わっている |
| 攻撃の発生位置 | 口、胸コア、武器など意図した位置に見える |
| 見た目 | 承認済みラフと同等以上 |
| 差分 | crop、再出力、ラベル変更だけではない |
| 目視確認 | RUN単体GIFとATTACK単体GIFを見ている |

1つでも満たせない場合は「未修正」と報告する。

### 2. 生成前に成功条件を固定する

Cobalt Pup の次回作業では、最低限以下を成功条件にする。

- 青いサイバー狼/狐系の見た目を維持する
- 大きい耳、白い頬毛、青い装甲、発光コアの魅力を残す
- RUNでは前足と後ろ足の接地が読める
- 後ろ足が一体化して滑って見えない
- ATTACKでは弾または光の発生源が明確に見える
- Idle、Run、Attack、Hitを別々のGIFで確認できる
- 文字やUIがキャラに重ならない
- 透過PNGの四隅alphaが0である

### 3. 素材の状態ラベルを分ける

今後、キャラクター素材は以下のどれかで明記する。

- `ROUGH_REVIEW`: ラフ案。方向性確認用
- `MOTION_REVIEW`: 動き確認用。まだゲーム内接続しない
- `RUNTIME_CANDIDATE`: ユーザー承認後、Unity取り込み候補
- `REJECTED`: 非採用。接続禁止

現在のCobalt関連GIFは `MOTION_REVIEW` 未満、または未修正確認素材。  
`RUNTIME_CANDIDATE` ではない。

### 4. Before / After を必ず示す

今後、修正を報告する場合は必ず以下を出す。

- 前回NGだった点
- 今回変えた点
- 新しいRUN GIF
- 新しいATTACK GIF
- まだ残る懸念

前回から問題箇所が変わっていない場合は、成果物として出さない。

crop、再出力、ラベル変更、GIF再生成だけの場合は「修正ではない」と明記する。

### 5. Claudeへの共有ルール

Claudeは、ユーザーが明示的に承認するまで、Cobalt Pup のアニメ素材をゲーム内に接続しない。

Claudeが参照すべきこと:

- この報告書
- `docs/CHARACTER_PIXEL_ART_PIPELINE.md`
- 非採用フォルダの素材は接続禁止
- review_gifsは修正済み素材ではない

## 次に正しくやるべきこと

既存の駄目な出力を小手先で直すのではなく、次は新規または編集済みフレームで、問題箇所そのものを直す。

次回の正しい順番:

1. Cobalt Pup の見た目を維持したまま、RUNフレームだけ作り直す
2. 後ろ足が自然に動くか、RUN単体GIFで確認する
3. ATTACKフレームだけ作り直す
4. 攻撃の発生源が自然か、ATTACK単体GIFで確認する
5. こちらでNGならユーザーに出さない
6. 合格した場合だけ、比較付きでユーザーに提示する

この段階では、ゲーム内接続はまだ行わない。

## 今回の結論

今回の失敗は、ユーザーの指示を理解していないように見える対応だった。  
実際に、指摘された箇所を直していないまま修正報告をしたため、そう受け取られて当然。

今後は、出力したかどうかではなく、ユーザーが指摘した見た目と動きが実際に変わったかを基準にする。
