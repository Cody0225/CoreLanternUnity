# Post-Release Operations Playbook

**作成日**: 2026-05-28
**用途**: Steam EA リリース後の日次・週次・月次オペレーション手順
**対象**: ユーザー (Embercore Studio 運営) + Claude (秘書サポート)

リリース後の運用ミスは「致命バグ放置」「コミュニティ放置」「機会損失」につながる。本書は日常運用を定型化して取りこぼし防止。

---

## 📅 リリース当日 (D-Day)

### 朝
- [ ] 最終ビルドの動作確認 (1 ラン通しプレイ)
- [ ] Steam ストアページの最終確認 (誤字 / リンク切れ / 画像)
- [ ] Twitter / Discord アナウンス文を準備
- [ ] 法務リンク (利用規約 / プライバシー) 有効確認

### リリース時刻 (Steam ボタン押下)
- [ ] Steamworks Portal で `Release Game` クリック
- [ ] 公開後 5 分で実際に Steam ストアでゲームが見えるか確認
- [ ] 自分で 1 本購入してダウンロード → 起動 (最終 sanity check)

### 直後 30 分
- [ ] Twitter / X で告知ポスト (画像付き、ハッシュタグ #indiegame #roguelite)
- [ ] Discord public channel で告知
- [ ] Note / Hatena Blog で詳細記事 (任意)
- [ ] itch.io ページに「Steam で公開しました」追記

### 当日中
- [ ] Steam Community ハブ巡回 (1 時間ごと)
- [ ] 配信者・実況者のリアクション検索 (YouTube / Twitch)
- [ ] 致命バグ報告に即対応 (V0.9.1 Hotfix 準備可能に)

- [ ] ポジティブな声 → `MARKETING_QUOTES.md` に追加
- [ ] KPI 数値更新 (`KPI_TRACKING.md` のダッシュボード)

## 📊 週次オペレーション (毎週日曜)

### 1. KPI レポート作成 (30 分)
- `KPI_TRACKING.md` の週次レポートセクションに追記
- DL 数 / 売上 / レビュー数 / フォロワー / 主要事象
- 前週比を計算

### 2. バックログ整理 (20 分)
- `BACKLOG_FROM_DEMO_FEEDBACK.md` の Open 項目をレビュー
- P0/P1 を翌週のパッチ計画に組み込む
- 重複や対応済を Done に移動

### 3. パッチ準備 (1-2 時間、月 1-2 回)
- 修正コミット → ビルド → 自分でプレイテスト
- Patch Notes 文面作成 (Claude 補助)
- Steam Build アップロード (`steamcmd`)
- ベータ branch でテスター招待 (任意)

### 4. SNS 発信 (15 分)
- 開発進捗を Twitter / X に投稿
- 例: 「今週は〇〇を改善しました」「次パッチで △△ 来ます」

### 5. コミュニティイベント (任意)
- Discord で「今週のお題」を提示 (例: 「最速 Wave 10 クリアタイム」)

## 📆 月次オペレーション (毎月 1 日)

### 1. 月次レビュー (1 時間)
- `KPI_TRACKING.md` の月次レビューセクションに追記
- 総 DL / 売上 / 入金額
- 主要トピック (パッチ / イベント / メディア露出)
- 改善点 / 学んだこと
- 翌月の重点

### 2. ロードマップ更新 (30 分)
- `EA_TO_1_0_ROADMAP.md` の進捗チェック
- マイルストーン完了マーク
- 遅延あれば原因分析と再計画

### 3. 経理処理 (1 時間)
- Steam 入金確認 (60 日後着金、最低 $100)
- itch.io 入金確認 (任意プラン)
- 経費・収益を会計ソフトに記録 (freee / マネーフォワード 等)
- 確定申告対応 (年 1 回、2-3 月)

### 4. 月次パッチリリース (任意)
- 月 1 回の大きめ更新を目標
- Patch Notes を Steam Community に投稿
- Twitter / Note で告知

## 🚨 緊急対応プロトコル

### 致命バグ報告が来た時
1. **再現確認** (5-30 分)
   - 報告内容を読み解く
   - 同環境で再現試行
   - 再現不可なら追加情報を依頼
2. **影響範囲評価** (5 分)
   - 全プレイヤーに発生する?
   - 特定環境 (Win 7 / 古い GPU 等) のみ?
   - 進行不能 vs 軽微なバグ?
3. **Hotfix 判断** (5 分)
   - 全プレイヤー × 進行不能 → 即 Hotfix (24-48 時間)
   - 特定環境 → 次パッチで対応 (1-2 週間)
4. **Hotfix 開発** (1-4 時間、Claude 連携)
   - 原因特定 → Edit ツールで修正 → Roslyn 確認
   - 必ず CLAUDE.md の検証フロー実行
   - バージョン番号 +0.0.1
5. **アップロード** (30 分)
   - Steam Build にアップ → `default` ブランチに割当
   - Patch Notes に「Hotfix: 〇〇修正」記載
6. **告知** (15 分)
   - Steam Community / Discord / Twitter
   - 「報告ありがとう」「修正しました」「ご迷惑おかけしました」

### Steam Content ID クレーム
1. 警告メール内容を Steamworks Portal で確認
2. 該当 BGM/SE を特定
3. `docs/AUDIO_LICENSE_LOG_TEMPLATE.md` でライセンス再確認
4. 正当な権利 → 反論 (Proof Files 提示)
5. グレー → 即差替 (procedural 仮版に戻す等)

### 大量ネガレビュー (1 日 5 件以上)
1. レビュー内容を全件読む
2. 共通する不満点を抽出
3. 緊急パッチ計画 or Public な説明文投稿
4. Steam Community で「対応中です」アナウンス
5. 必要に応じて価格を一時的に下げる (50% OFF セール)

### サーバーダウン (Steam / itch.io 側)
- ユーザー側で対応不可
- Twitter で「現在 Steam が不安定です」アナウンスする程度

## 💸 収益管理

### Steam 収益フロー
1. プレイヤー購入 (例: $2.99)
2. Steam が 30% 控除 → $2.09 がユーザー取り分
3. 30%源泉徴収 (W-8BEN なしの場合) → 提出済なら 0%
4. 月締めで翌月後半に集計
5. **60 日後** に登録口座に振込 (最低 $100 から)
6. 円換算 (約 ¥315) → 売上として記帳

### itch.io 収益フロー
1. プレイヤー購入
2. itch.io 手数料 (任意設定、デフォルト 10%)
3. PayPal / Stripe 経由で即時 or 月次振込

### 経費管理
記帳すべき経費:
- Steamworks 開発者登録 $100
- ドメイン (`embercore.studio`) 年 ¥1,500-¥5,000
- 商用素材ライセンス費 (BGM/SE 購入時)
- 開発機材 (PC / Unity プロ版 / etc.)
- 弁護士相談料 (利用規約レビュー時)

### 確定申告
- 個人事業主: 年 1 回、2-3 月
- 法人化: 売上 500-800 万円超で検討
- 税理士相談推奨 (年 ¥30,000-¥100,000)

## 🛡 リスク管理

### 開発者個人のリスク
| リスク | 対応 |
|---|---|
| 体調不良で更新止まる | コミュニティに「休養中」アナウンス、無理しない |
| モチベ低下 | 短期目標を設定、コミュニティの好意的な声を読み返す |
| 燃え尽き | 月次パッチを「月 1 回でも OK」と緩める |

### 法的リスク
| リスク | 対応 |
|---|---|
| 著作権クレーム | `AUDIO_LICENSE_LOG_TEMPLATE.md` の Proof Files で反論 |
| 商標訴訟 | `Embercore Studio` 名で類似登録なし確認、衝突時はブランド変更 |
| 不当返金要求 | Steam のポリシーに準拠、Steam サポートに引き継ぎ |
| 詐欺・成りすまし | 「公式アカウントは @embercore_studio のみ」周知 |

### コミュニティリスク
| リスク | 対応 |
|---|---|
| 荒らし | Discord moderation tool で BAN |
| 政治的議論 | チャンネルルールに「ゲーム以外の議論禁止」明記 |
| ハラスメント | 即 BAN、公開告知不要 |
