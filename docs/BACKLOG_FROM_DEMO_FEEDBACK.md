## 📝 個別エントリー テンプレート

新規フィードバックを追加する時は以下のフォーマット:

```markdown
### [P?-001] タイトル
- **日付**: YYYY-MM-DD
- **ソース**: itch.io コメント / Steam / Discord / etc.
- **報告者**: (ユーザー名、希望者のみ)
- **再現性**: 100% / 頻繁 / たまに / 不明
- **環境**: Windows 11 / GTX 1660 / 16GB RAM 等
- **症状**: 何が起きた
- **期待動作**: 何が起きるべき
- **対応**: 修正方法 / 関連コード行
- **ステータス**: Open / In Progress / Done / Won't Fix
- **Closed Date**: YYYY-MM-DD
```

## 🎯 受け取り方の指針

### 良いフィードバックの例
✅ 「Wave 7 で Elite 4 体同時湧きすると、5 秒以内にコアが破壊される。明らかに難易度ジャンプが激しい。」
- 具体的な Wave / 状況 / 結果が明示されている → 再現・調整しやすい

### 受け取りにくいフィードバックの例
❌ 「難しい」「面白くない」「もっと良くしてほしい」
- 具体性ゼロ → 何を改善すべきか判断不能 → コメント返信で詳細を確認

### 返信テンプレ
```
ご報告ありがとうございます。
具体的な状況を教えていただけますか?
- 何 Wave で起きましたか?
- どの相棒キャラを使っていましたか?
- どのモジュールを取得していましたか?
- スクリーンショットがあれば添付お願いします。

確認次第、対応します。
— Embercore Studio
```

## 🔄 運用フロー

1. **受信** (毎日 1-2 回チェック):
   - itch.io コメント欄
   - Steam ストアレビュー / フォーラム
   - Discord #bug-report / #feedback
   - Twitter メンション / DM
   - メール: contact@embercore.studio

2. **分類** (即座):
   - バグ報告 → 再現可能か確認 → P0 / P1 へ
   - 改善要望 → 既存項目に統合 or 新規 P2 / P3 で起票
   - ポジティブな感想 → `MARKETING_QUOTES.md` (要新規作成) へ移動

3. **対応** (週次でレビュー):
   - P0: 即修正 → Hotfix リリース
   - P1: 次パッチ (2-4 週後) に含める
   - P2: 月次パッチ or 1.0 リリース時に検討
   - P3: バックログとして温存

4. **告知** (パッチリリース時):
   - Steam: Community Hub に Patch Notes 投稿
   - itch.io: Devlog に変更内容を記載
   - Twitter: 主要修正をアナウンス
