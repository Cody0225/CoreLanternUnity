>

> 本書の RUN/ATTACK/HIT/単体GIF 提出物は **将来アニメ機構を入れる時用に休眠**。
> 今の静止画レビューでは「RUN/ATTACK単体GIF必須」は適用せず、代わりに静止画の

> 陰影3階調(べた塗り禁止)・本体色サンプル検証**を秘書レビューでも確認する。

## 目的

ユーザーの意向は「やり取りの回数を減らす」「無駄な確認物を出さない」「チーム内で先に指摘されそうな場所を潰す」こと。

そのため、キャラクター画像・モーション作業では、ユーザーへ見せる前に必ず秘書レビューを挟む。

この運用の最優先ルールは「懸念が1つでも残る場合、修正済みとして提示しない」。  
少しでも気になる点があるなら、ユーザーへ確認物として出す前に止める。

## 役割

### 制作担当

- 画像生成、ピクセル調統一、透過処理、GIF化を行う
- 指摘事項に対して実際に変化がある素材だけを候補にする
- `docs/CHARACTER_ANIMATION_GLOBAL_QA.md` のゲートを通す

### 秘書レビュー担当

- ユーザーやClaudeから突っ込まれそうな点を先に洗い出す
- 見た目、動き、攻撃発生源、縮小表示、命名、接続可否を確認する
- OK/NGを短くまとめ、NGがある場合はユーザーに出さず制作担当へ戻す
- ユーザーへは「通したもの」「止めたもの」「残る懸念」だけを報告する

秘書レビュー担当は、制作担当の自己OKをそのまま通さない。  
ユーザー視点とClaude接続視点で、先に突っ込まれそうな場所を潰す。

## 必須提出物

キャラ画像・モーションをユーザーに見せる場合、原則として以下を揃える。

| 提出物 | 目的 |
|---|---|
| RUN/MOVE単体GIF | 足運び、浮遊、移動の自然さを見る |
| ATTACK単体GIF | 攻撃発生源、溜め、発射、反動を見る |
| 64px / 96px / 128px縮小確認画像 | ゲーム内サイズで読めるか見る |
| Before / After比較 | 指摘箇所が本当に変わったか見る |
| 透過PNGまたは透過シート | 四隅alphaとUnity取り込み前提を見る |

複合プレビューだけでは提出物として不十分。  
RUN/MOVEとATTACKは必ず単体で確認する。

## ユーザーへ出す前の秘書チェック

| 項目 | 確認内容 |
|---|---|
| 見た目 | 前回より劣化していないか |
| キャラ一致 | 名前・説明・役割と見た目が一致しているか |
| 体型 | 四足/二足/浮遊など、体型に合った動きか |
| RUN/MOVE | 足や体の動きが自然か。滑っていないか |
| ATTACK | 攻撃の発生源が自然で、絵として読めるか |
| ATTACKの流れ | 溜め、発射、反動、戻りがあるか |
| HIT | 被弾時に何が起きたか分かるか |
| 縮小表示 | 64px / 96px / 128pxでシルエットが読めるか |
| 透過 | 透過PNGの四隅alphaが0か |
| プレビュー | GIF内で文字やUIがキャラに重なっていないか |
| 差分 | 指摘された箇所が前回から本当に変わったか |
| 接続可否 | `ROUGH_REVIEW` / `MOTION_REVIEW` / `RUNTIME_CANDIDATE` / `REJECTED` が明確か |

## 四足キャラの追加チェック

四足キャラは、特に足運びで破綻しやすい。以下を追加で確認する。

- 前左 + 後右、前右 + 後左の対角ペアが読める
- 後ろ足が胴体に隠れすぎて、同じ足だけ動いて見えない
- 接地足と浮いている足がフレームごとに分かる
- 影の位置が体だけ横滑りしているように見せていない
- 胴体の上下動が足運びと合っている
- 尻尾や耳の揺れでごまかしていない

## 攻撃モーションの追加チェック

攻撃は、発生源だけでなく流れを見る。

- 溜め: 発生源に光や構えが集まる
- 発射: 弾やレーザーが発生源から出ている
- 反動: 口、頭、首、胸コア、武器など発生源に応じた戻りがある
- 戻り: 攻撃後に自然にIdle/Move姿勢へ戻る

口から撃つ場合は、口元の発光と頭/首の反動を確認する。  
胸コアから撃つ場合は、胸コアの溜めと体幹の反動を確認する。

## NG時の扱い

1つでも重要NGがある場合、ユーザーに「確認お願いします」と出さない。

必ず以下のどれかにする。

- 制作担当へ戻して修正
- 失敗素材として隔離
- 「未修正」と明記して、次に必要な作業だけ報告

同じキャラ・同じ問題で内部NGが2回続いた場合は、そこで生成を止める。  
無限に微妙なGIFを作らず、ユーザーへ「どの方向で直すべきか」を短く相談する。

## 秘書報告フォーマット

ユーザーへ報告する場合は、以下の短い形式にする。

```text
秘書レビュー:
- 通過: 〇〇
- 止めた点: 〇〇
- 修正済み: 〇〇
- 残る懸念: 〇〇
- 次の確認対象: RUN単体GIF / ATTACK単体GIF
```

問題が残っている場合は、成果物の大量提示をしない。  
必要な確認対象だけに絞る。

crop、再出力、ラベル変更、GIF再生成だけの場合は、毎回「修正ではない」と明記する。

## 事前確認が必要なケース

以下は作業前またはユーザー提示前に必ず確認する。

- 攻撃発生源を口にするか、胸コアにするか、武器にするか迷う
- 四足の足運びがラフ上で破綻している
- 見た目は良いが動きが悪い
- 動きは良いがキャラらしさが落ちている
- 進化後やクロス進化で、元キャラの核が消えている
- ゲーム内サイズで潰れる可能性がある

## Claude共有

Claudeには以下を共有する。

- 秘書レビューを通っていない素材は接続しない
- `REJECTED` と明記された素材は使わない
- `MOTION_REVIEW` はゲーム内接続候補ではない
- `RUNTIME_CANDIDATE` になった素材だけ接続検討する
- 共有時は、接続してよいファイル名と接続禁止ファイル名を明記する

## 結論

ユーザーへ見せる前に、制作担当と秘書レビュー担当の2段階で見る。  
「少しでも気になる点があるなら先に止める」を原則にする。
